# VPS Scope

> ابزار ممیزی امنیت و وضعیت اجرای VPSهای دارای پراکسی شخصی، تونل و شبکهٔ خصوصی.

VPS Scope روی Ubuntu و Debian اجرا می‌شود. ابزار ابتدا یک خط مبنای گسترده از امنیت میزبان را بررسی می‌کند: حساب‌ها و SSH، sudo، فایروال، محافظت در برابر تلاش‌های ورود، به‌روزرسانی‌ها، بسته‌ها، سرویس‌های systemd، Docker، گواهی‌های TLS، لاگ‌ها، منابع سیستم و نشانه‌های ماندگاری مشکوک. این نتایج برای VPSهای بدون پراکسی نیز مفید هستند.

در یک سرور پراکسی، این خط مبنای عمومی کافی نیست. یک پورت عمومی ممکن است ورودی مورد انتظار Reality، Hysteria2 یا Shadowsocks باشد؛ یا ممکن است به پنل مدیریت، مسیر اشتراک یا API داخلی تعلق داشته باشد که نباید برای تمام اینترنت باز باشد.

بنابراین VPS Scope وضعیت میزبان لینوکس و بار کاری پروکسی را در یک زنجیره شواهد قرار می‌دهد: پایگاه داده پنل و پیکربندی پروکسی نشان می‌دهند «چه چیزی باید اجرا شود»، systemd، Docker، فرایندها و شنونده‌های واقعی نشان می‌دهند «اکنون چه چیزی اجرا می‌شود»، و فایروال میزبان و پراکسی معکوس نشان می‌دهند «از بیرون چگونه می‌توان به آن دسترسی داشت». گزارش در پایان تلاش می‌کند چند پاسخ مستقیم بدهد:

- آیا خطرات واضحی برای SSH، حساب ها، فایروال ها، به روز رسانی ها و خدمات سیستم وجود دارد یا خیر.
- آیا ورودی‌های Reality، Hysteria2 و Shadowsocks واقعاً در حال گوش‌دادن هستند و با فایروال سازگارند؛
- آیا پنل های مدیریتی مانند S-UI و 3x-ui به طور تصادفی برای کل شبکه عمومی باز شده اند یا خیر.
- آیا پیکربندی، پایگاه دادهٔ پنل، فرایندها و شنونده‌های واقعی با یکدیگر سازگارند؛
- آیا مشکلاتی وجود دارد که بر ادامه عملکرد سرویس‌های اصلی، گواهی‌های TLS، گزارش‌ها و منابع سیستم تأثیر می‌گذارد.

این ابزار فقط نام نرم‌افزار را تشخیص نمی‌دهد و یک اسکن پورت همراه با چک‌لیست Linux هم نیست. VPS معمولی خط مبنای امنیت میزبان را دریافت می‌کند؛ VPS پراکسی علاوه بر آن، رابطهٔ میان ورودی‌های پراکسی، پنل مدیریت، اشتراک‌ها، APIهای کنترلی، کانتینرها و پراکسی معکوس را نشان می‌دهد.

```bash
curl -fsSL https://github.com/sakkaku404/vps-scope/releases/latest/download/run.sh | sudo bash
```

این فرمان ابتدا SHA-256 فایل دانلودشده را بررسی می‌کند و سپس آن را اجرا می‌کند. اگر `cosign` نصب نباشد، فقط یک هشدار کوتاه دربارهٔ تأیید نشدن امضای ناشر نمایش داده می‌شود و دیگر نیازی به وارد کردن `continue` نیست.

در حالت تعاملی می‌توان زبان چینی ساده، انگلیسی، روسی یا فارسی را انتخاب کرد. برای اجرای غیرتعاملی از `--lang zh-CN`، `--lang en`، `--lang ru-RU` یا `--lang fa-IR` استفاده کنید.

برای رد شدن از پرسش‌ها، گزینه‌های ممیزی را پس از `bash -s --` قرار دهید. گزینه‌هایی که با `--` آغاز می‌شوند به‌طور خودکار به فرمان `audit` داده می‌شوند:

```bash
curl -fsSL https://github.com/sakkaku404/vps-scope/releases/latest/download/run.sh | sudo bash -s -- --lang fa-IR --profile proxy
```

به‌طور پیش‌فرض، نتیجه فقط در ترمینال نمایش داده می‌شود و هیچ فایل گزارشی نوشته نمی‌شود. برای ذخیرهٔ گزارش‌های HTML، Markdown و JSON گزینهٔ خروجی ۲ یا ۳ را انتخاب کنید. VPS Scope هیچ اصلاحی ندارد و SSH، فایروال‌ها، سرویس‌ها، حساب‌ها یا بسته‌ها را تغییر نمی‌دهد.

ممیزی پیش‌فرض همچنین فایل‌های اجرایی متعلق به S-UI، 3x-ui، sing-box، Xray، Nginx یا دیگر بارهای کاری تحت ممیزی را اجرا نمی‌کند و فقط پیکربندی، پایگاه داده و وضعیت جاری سیستم را می‌خواند. فقط با انتخاب صریح `--native-self-test`، پس از بررسی مالکیت و مجوزها، این برنامه‌ها اجرا می‌شوند؛ کد شخص ثالث با سطح دسترسی فرایند ممیزی اجرا خواهد شد که در اجرای `sudo` همان دسترسی root است.

## یک مثال واقعی

موارد زیر مربوط به یک VPS آزمایشی است که S-UI 1.5.3 و sing-box را اجرا می کند و آدرس و اطلاعات نامربوط حذف شده است:

```text
نتیجه ممیزی VPS پروکسی
────────────────────────────────────────────────────────────────────
شناسایی شد: S-UI، sing-box
ورودی‌های پروکسی    PASS
  چهار ورودی تأیید شد؛ پیکربندی، شنونده‌های فعال و فایروال میزبان سازگار هستند.
صفحه مدیریت         RISK/HIGH
  S-UI 56709/tcp · گوش‌دادن عمومی · فایروال مجاز
  TLS فعال · مسیر غیراستاندارد · صفحه مدیریت از کل اینترنت قابل دسترسی است
پیکربندی و اجرا     INFO
  پیکربندی به‌صورت ایستا تحلیل شد؛ برنامهٔ پنل یا هستهٔ پراکسی اجرا نشد.

ورودی‌های پروکسی:
  443/tcp    sing-box/vless (reality)       عمومی · مجاز · PASS
  443/udp    sing-box/hysteria2             عمومی · مجاز · PASS
  32003/tcp  sing-box/shadowsocks           عمومی · مجاز · PASS
  32003/udp  sing-box/shadowsocks           عمومی · مجاز · PASS
```

یک پنل و فرایند هسته می‌توانند چند پورت عمومی داشته باشند. ممیزی عمومی VPS معمولاً همهٔ آن‌ها را فقط «پورت باز» می‌نامد. VPS Scope پایگاه دادهٔ پنل، پیکربندی پراکسی، فرایندها، شنونده‌ها و فایروال را کنار هم می‌گذارد تا ورودی‌های عادی پراکسی با پنل مدیریتی که باید محدود شود اشتباه گرفته نشوند.

تفاوت اصلی با ممیزی عمومی VPS همین است: بررسی‌های ضروری SSH، حساب‌ها، به‌روزرسانی و ماندگاری حفظ می‌شوند، اما نقش هر ورودی پراکسی نیز جداگانه ارزیابی می‌شود.

## پس از بررسی چه چیزی دریافت خواهید کرد؟

به‌طور پیش‌فرض نتیجه فقط در ترمینال نمایش داده می‌شود. با انتخاب گزینهٔ خروجی ۲ یا ۳، یا استفاده از `--format bundle`، یک ممیزی همان مجموعهٔ نتایج را در چهار قالب ذخیره می‌کند:

```text
report.fa-IR.html   توصیه می‌شود؛ پس از دانلود با مرورگر باز کنید
report.fa-IR.txt    نسخه متنی برای ترمینال
report.fa-IR.md     گزارش کامل Markdown
report.json         داده کامل ماشین‌خوان برای مقایسه و خط مبنا
manifest.json       فهرست SHA-256 چهار فایل گزارش بالا
```

یعنی پوشه شامل **چهار قالب از یک نتیجهٔ ممیزی و یک فهرست صحت‌سنجی** است؛ ممیزی چهار بار اجرا نشده است.

`report.json` رکورد اصلی ممیزی است که همه قالب‌ها از آن استفاده می‌کنند. این فایل ۵۵ شناسه پایدار بررسی، وضعیت‌ها، شدت‌ها و کدهای علت را نگه می‌دارد و همچنین نمای ساخت‌یافته‌ای از استقرار ارائه می‌دهد: مؤلفه‌های شناسایی‌شده، نقاط پایانی سرویس، ارتباط‌های پراکسی و پراکسی معکوس و میزان پوشش شواهد. HTML، Markdown، مقایسهٔ تاریخی و خط مبنا همین داده‌های ساخت‌یافته را می‌خوانند و متن ترمینال را دوباره تفسیر نمی‌کنند. گزارش‌های قدیمی `schema 1.0` همچنان قابل خواندن هستند. `vps-scope verify report.json` قرارداد معنایی را بررسی می‌کند؛ برای یک بستهٔ کامل، مجموعهٔ فایل‌ها و SHA-256 نیز با `manifest.json` سنجیده می‌شود.

پس از ذخیره، برنامه ابتدا مسیر ثابت `latest` گزارش HTML را نشان می‌دهد. ساده‌ترین راه این است که SFTP را در نرم‌افزار SSH باز کنید، به `/root/vps-scope-reports/latest/` بروید (برای کاربر غیر root از مسیر نمایش‌داده‌شده توسط برنامه استفاده کنید) و `report.fa-IR.html` را دانلود کنید. همچنین می‌توانید روی رایانهٔ خود اجرا کنید:

```bash
scp <SSH_HOST>:'/root/vps-scope-reports/latest/report.fa-IR.html' .
```

`<SSH_HOST>` را با نشانی IP، دامنه یا نام مستعار SSH که معمولاً برای این VPS استفاده می‌کنید جایگزین کنید. همان درگاه، فایل کلید یا تنظیمات `ssh-agent` ورود عادی را نیز به‌کار ببرید؛ VPS نمی‌تواند محل نگهداری کلید خصوصی روی رایانهٔ کاربر را تشخیص دهد. پوشهٔ تاریخچهٔ زمان‌دار و فهرست پنج فایل همچنان در ادامه نمایش داده می‌شوند.

پس از اجرای موقت یک‌خطی، فایل‌های گزارش باقی می‌مانند اما برنامهٔ دانلودشده حذف می‌شود. دستورهای زیر فقط زمانی در دسترس‌اند که VPS Scope نصب شده باشد:

```bash
sudo vps-scope report show  # نمایش دوباره آخرین نتیجه در ترمینال
sudo vps-scope report path  # نمایش پوشه آخرین گزارش
sudo vps-scope report list  # فهرست گزارش‌های ذخیره‌شده
```

گزارش HTML ابتدا وضعیت ورودی‌های پراکسی، پنل مدیریت، سازگاری پیکربندی و اجرا، دسترس‌پذیری سرویس و امنیت پایهٔ Linux را خلاصه می‌کند. سپس پیشنهادها و جزئیات فنی را نشان می‌دهد. صفحه بدون بارگیری اسکریپت یا فونت خارجی، جستجو، فیلتر وضعیت و بازکردن شواهد را پشتیبانی می‌کند.

## VPS Scope چه چیزهایی را بررسی می‌کند؟

### ورودی‌های پراکسی و پنل‌های مدیریت

- ورودی پراکسی، پنل مدیریت، مسیر اشتراک و API کنترلی را از هم جدا می‌کند.
- پیکربندی پروتکل را با شنونده‌های TCP/UDP، مالک فرایند و فایروال IPv4/IPv6 مرتبط می‌کند.
- ورودی پیکربندی‌شده ولی غیرفعال، مسدودشده با فایروال، متعلق به فرایند نادرست یا شنوندهٔ باقی‌مانده پس از غیرفعال‌سازی را پیدا می‌کند.
- مشخص می‌کند پنل روی آدرس عمومی، فقط loopback یا از طریق Nginx، Caddy و HAProxy در دسترس است.
- مسیر ریشه/پیش‌فرض و وضعیت TLS را گزارش می‌کند، اما مسیر مخفی را کنترل دسترسی نمی‌داند.

### پیکربندی و وضعیت در حال اجرا

- پیکربندی sing-box و Xray را به‌طور پیش‌فرض ایستا تحلیل می‌کند؛ خودآزمایی برنامه‌ها فقط با درخواست صریح اجرا می‌شود.
- پایگاه دادهٔ S-UI و 3x-ui/x-ui، پیکربندی تولیدشده، فرایندها و شنونده‌ها را مقایسه می‌کند.
- رابطهٔ اجرایی Reality، Hysteria2، TUIC، Trojan، Shadowsocks، WireGuard و OpenVPN را بررسی می‌کند.
- تعداد خطاهای احراز هویت، handshake، DNS، TLS، مسیریابی و ورود به پنل را بدون کپی لاگ خام یا دادهٔ کاربر گزارش می‌کند.
- اعتبار گواهی، برنامه و نتیجهٔ اخیر تمدید و reload سرویس را بررسی می‌کند.

### Docker و پایه سیستم

- privileged mode، host network، capabilities خطرناک، Docker socket و پورت‌های منتشرشده را بررسی می‌کند.
- INPUT، FORWARD و DOCKER-USER را با انتشار واقعی کانتینر مرتبط می‌کند.
- SSH، حساب‌ها، sudo، Fail2ban/CrowdSec، به‌روزرسانی‌ها و سرویس‌های systemd را بررسی می‌کند.
- OOM، core dump، فضای دیسک و inode، ماندگاری لاگ و ورودی‌های مشکوک راه‌اندازی را بررسی می‌کند.
- حساب UID 0 اضافی، کلید SSH غیرعادی، برنامهٔ در حال اجرا از پوشهٔ موقت و فایل اجرایی حذف‌شده ولی فعال را پیدا می‌کند.

## سطح پشتیبانی

تشخیص نام یک محصول به معنی پشتیبانی کامل از همهٔ نسخه‌ها، forkها و روش‌های استقرار آن نیست. سطح پشتیبانی فعلی در سه گروه بیان می‌شود:

### بیشترین میزان اعتبارسنجی

- S-UI
- 3x-ui / x-ui
- sing-box
- هسته Xray

این مؤلفه‌ها روی VPSهای یک‌بارمصرف، همراه با پایگاه دادهٔ واقعی پنل، پیکربندی، شنونده‌ها، فایروال و ورودی‌های پراکسی آزمایش شده‌اند.

### آداپتورها و بررسی‌های اختصاصی

- Hiddify
- Marzban
- Outline
- WireGuard
- OpenVPN
- Hysteria2، TUIC، تروجان، Shadowsocks

### تشخیص رابطه‌های استقرار

- Docker و Docker Compose
- Nginx
- Caddy
- HAProxy

برای نسخه‌های خاص، روش‌های استقرار و معنای تأییدشده، به [سازگاری پروکسی](PROXY-COMPATIBILITY.md) و [ماتریس سازگاری](COMPATIBILITY-MATRIX.md) مراجعه کنید. هنگام مواجهه با ساختارهای ناشناخته پایگاه داده، اهداف پویای پراکسی معکوس یا شواهد ناقص، نتیجه `UNKNOWN` باقی می‌ماند و برنامه وانمود نمی‌کند که امنیت تأیید شده است.

### اعتبارسنجی آزمایشگاهی

پیش از انتشار v1.1.0، پنج VPS یک‌بارمصرف دو دور ممیزی معمولی و عمیق، اعتبارسنجی بستهٔ گزارش، تولید بستهٔ پشتیبانی حذف‌شده از شناسه‌ها و آزمون TCP/UDP میان میزبان‌ها را کامل کردند. هر میزبان تمام ۵۵ نتیجه را بدون تغییر ناخواسته در وضعیت، شدت، کد علت و رابطهٔ نقاط پایانی تولید کرد؛ میزبان ۵۱۲ مگابایتی نیز ممیزی عمیق را به پایان رساند. پس از آزمون، ماشین‌ها، قوانین موقت و فرایندهای کمکی حذف شدند.

این اطلاعات سابقهٔ یک آزمایش کنترل‌شده هستند، نه تضمین برای همهٔ نسخه‌های سیستم، پنل یا شبکهٔ ابری. نقش میزبان‌ها و قرارداد تکرارپذیر در [راهنمای آزمایش](TESTING.md) و [آمادگی انتشار](READINESS.md) آمده است.

## چگونه نتایج را درک کنیم

گزارش یک امتیاز عددی و غیرقابل‌توضیح برای امنیت تولید نمی‌کند. چهار وضعیت استفاده می‌شود:

- `PASS`: شواهد از نتیجهٔ فعلی پشتیبانی می‌کنند، اما امنیت دائمی سرور را تضمین نمی‌کند.
- `RISK`: مشکل یا وضعیتی پیدا شده که نیاز به بررسی دارد.
- `INFO`: اطلاعات موجودی یا زمینه‌ای که به‌تنهایی مشکل محسوب نمی‌شود.
- `UNKNOWN`: شواهد کافی نیست یا جمع‌آوری شکست خورده است؛ این وضعیت `PASS` نیست.

هنگام خواندن ابتدا به این موارد توجه کنید:

1. **نتیجهٔ VPS پراکسی**: آیا ورودی‌های پراکسی و پنل مدیریت وضعیت مناسبی دارند؟
2. **اقدام‌های اولویت‌دار**: چه مواردی باید زودتر بررسی شوند؟
3. **اثر احتمالی بر دسترس‌پذیری**: مشکلات ورودی، فایروال، گواهی یا بازیابی سرویس.
4. **شواهد ناکافی**: بخشی که ابزار نمی تواند به طور قابل اعتماد قضاوت کند

«شاخص نتایج بازرسی» فهرست وضعیت 55 بازرسی است. شواهد کامل در HTML، Markdown و JSON قرار دارد.

## نصب و دستورات رایج

در صورت نیاز به بررسی های منظم، می توانید نصب کنید:

```bash
curl -fsSL https://github.com/sakkaku404/vps-scope/releases/latest/download/install.sh | sudo bash
sudo vps-scope
```

بدون پارامتر، راهنمای تعاملی با زبان چینی ساده، انگلیسی، روسی یا فارسی باز می‌شود. ممیزی را می‌توان مستقیم نیز اجرا کرد:

```bash
sudo vps-scope audit --lang fa-IR --profile proxy
sudo vps-scope audit --profile custom --expect-public 22/tcp,443/tcp
sudo vps-scope audit --deep
# اختیاری: اجرای خودآزمایی بومی برنامه‌های محلی پس از بررسی اعتماد
sudo vps-scope audit --native-self-test
```

### پروفایل سرور چه چیزی را تغییر می‌دهد؟

پروفایل هیچ‌یک از بررسی‌های پایه را حذف نمی‌کند و چیزی را روی سرور تغییر نمی‌دهد. فقط برای تشخیص اینکه یک شنوندهٔ عمومی با نقش این میزبان سازگار است یا نه، زمینه فراهم می‌کند.

| پروفایل | کاربرد | اثر بر تفسیر نتیجه |
|---|---|---|
| `auto` | انتخاب پیشنهادی در صورت تردید | با استفاده از فرایندها، systemd، Docker و مسیرهای شناخته‌شدهٔ پیکربندی، نقش `general`، `proxy`، `web`، `docker` یا `mixed` را تشخیص می‌دهد |
| `general` | VPS معمولی Linux | وجود ورودی عمومی پراکسی، وب یا کانتینر را از پیش فرض نمی‌کند |
| `proxy` | میزبان‌های sing-box، Xray، S-UI، 3x-ui، Hysteria2 و مشابه | ورودی پراکسی دارای شواهد را مورد انتظار می‌داند، اما پنل، اشتراک و API کنترلی را جداگانه ممیزی می‌کند |
| `web` | Nginx، Caddy، HAProxy، Apache و ورودی‌های وب | زمینهٔ ورودی وب را اضافه می‌کند |
| `docker` | میزبانی که بیشتر سرویس‌ها را با Docker منتشر می‌کند | انتشار کانتینر، FORWARD و DOCKER-USER را در نظر می‌گیرد |
| `mixed` | میزبان دارای چند نقش | زمینه‌های مربوط را با هم ترکیب می‌کند |
| `custom` | پورت‌های عمومی مورد انتظار را دقیقاً می‌دانید | به `--expect-public PORT/tcp,PORT/udp` نیاز دارد |

انتخاب `proxy` یک پنل عمومی را امن نمی‌کند. اگر مطمئن نیستید، `auto` را انتخاب کنید؛ گزارش هم پروفایل انتخاب‌شده و هم نقش تشخیص‌داده‌شده را ثبت می‌کند.

حالت تعاملی و فرمان اجرای موقت به‌طور پیش‌فرض گزارش را فقط در ترمینال نشان می‌دهند. برای نمایش و ذخیرهٔ هم‌زمان گزارش کامل، گزینهٔ خروجی ۲ را انتخاب کنید یا مسیر را به‌صورت دستی مشخص کنید:

```bash
sudo vps-scope audit --lang fa-IR --profile proxy \
  --format bundle --also-terminal --output ./reports/my-vps
```

اگر از قبل JSON دارید، می توانید گزارش را به صورت آفلاین و بدون اتصال مجدد به سرور بازسازی کنید:

```bash
vps-scope render --lang fa-IR --format html --output report.html report.json
vps-scope verify report.json
vps-scope verify ./reports/my-vps
```

مقایسه دو نتیجه از یک سرور:

```bash
vps-scope diff old.json new.json
vps-scope baseline create report.json baseline.json
vps-scope baseline check baseline.json report-new.json
```

### سیاست صریح و مشاهده از میزبان دوم

شناسایی خودکار پنل‌ها و ورودی‌های رایج پراکسی را پیدا می‌کند، اما محدودیت منبع، نیاز TLS و مسیر پنل یا مسیر خروجی IPv4/IPv6 مورد نظر شما را نمی‌داند. فایل policy این انتظارها را بدون ذخیرهٔ اعتبارنامه و بدون تغییر سرور ثبت می‌کند:

```bash
vps-scope policy init policy.json
# نقش‌ها، سطح دسترسی و انتظارهای خروجی را ویرایش کنید
vps-scope policy validate policy.json
sudo vps-scope audit --profile proxy --policy policy.json
```

برای بررسی دسترسی واقعی از شبکه‌ای دیگر، روی VPS ممیزی‌شده یک طرح بدون اطلاعات محرمانه بسازید، آن را روی VPS کنترل‌شده دیگری اجرا و نتیجه را وارد کنید:

```bash
vps-scope probe plan --target 203.0.113.10 --output plan.json report.json
vps-scope probe run --output observation.json plan.json
vps-scope probe import --output report-observed.json report.json observation.json
```

نتیجه TCP با سیاست اعلام‌شده مقایسه می‌شود. UDP عمداً `UNKNOWN` باقی می‌ماند، زیرا یک دیتاگرام دلخواه موفقیت دست‌دهی واقعی را ثابت نمی‌کند. `WORK-017` نیز نسخه‌های 3x-ui، sing-box و Xray را آفلاین با تصویر داخلی هشدارهای رسمی تطبیق می‌دهد. نسخه آسیب‌پذیر `RISK` و نسخه نامشخص یا پایگاه قدیمی `UNKNOWN` است؛ نبود تطبیق به معنی نبود سایر آسیب‌پذیری‌ها نیست.

پیش از انتشار گزارش، یک نسخهٔ حذف‌شده از شناسه‌های حساس بسازید:

```bash
vps-scope redact --format markdown --output public.md report.json
```

ممکن است گزارش‌ها همچنان حاوی روابط حساس استقرار باشند؛ پیش از اشتراک‌گذاری آن‌ها را بررسی کنید. قوانین کامل در [بیانیه حریم خصوصی](PRIVACY.md) آمده است.

## دامنهٔ پشتیبانی و محدودیت‌ها

در حال حاضر موارد زیر پشتیبانی می‌شوند:

- Ubuntu و Debian
- Linux روی `amd64` و `arm64`
- استقرار معمولی با systemd و استقرار Docker

VPS Scope پیکربندی و وضعیت قابل مشاهده از داخل VPS را بررسی می‌کند، اما نمی‌تواند:

- ثابت کند سرور قطعاً آلوده یا نفوذشده نیست؛
- فایروال ابری یا security group ارائه‌دهنده را از داخل مهمان بخواند؛
- جای آزمایش با کلاینت واقعی یا مشاهده از شبکه‌ای دیگر را بگیرد؛
- درک درست یک schema جدید و هنوز پشتیبانی‌نشدهٔ پنل را تضمین کند.

بررسی‌های پیش‌فرض برای اجرای منظم مناسب‌اند. `--deep` بررسی SUID/SGID، file capabilities و یکپارچگی بسته‌های نصب‌شده را اضافه می‌کند و زمان بیشتری می‌برد. بررسی عمیقی که اجرا نشده باشد «اجرا نشده» گزارش می‌شود، نه `PASS`.

## بارگیری و تأیید امنیتی

اسکریپت‌های اجرای موقت و نصب خودشان نیز دارایی‌های امضاشدهٔ Release هستند. پس از اجرا، همیشه SHA-256 فایل باینری دانلودشده را بررسی می‌کنند و اگر `cosign` موجود باشد، امضای بدون کلید GitHub Actions آن را نیز تأیید می‌کنند. بدون `cosign`، اسکریپت اجرای موقت یک هشدار کوتاه نمایش می‌دهد و خودکار ادامه می‌دهد؛ `VPS_SCOPE_REQUIRE_SIGNATURE=1` تأیید موفق امضا را الزامی می‌کند و در غیر این صورت اجرا متوقف می‌شود. نصب دائمی همچنان به تأیید تعاملی نیاز دارد و خودکارسازی باید با `--allow-unsigned` یا `VPS_SCOPE_ALLOW_UNSIGNED=1` نصب صرفاً مبتنی بر checksum را صریحاً بپذیرد.

دستور `curl | bash` نمی‌تواند پیش از شروع اجرا، خود اسکریپت راه‌انداز را احراز کند. برای مسیر کاملاً قابل‌تأیید، اسکریپت یک نسخهٔ ثابت و Sigstore bundle آن را دانلود و بررسی کنید، سپس اسکریپت را اجرا کنید تا فایل باینری را نیز بررسی کند. فرمان‌های دقیق، منشأ ساخت و مجوزها در [مستندات زنجیره تأمین](SUPPLY-CHAIN.md) آمده است.

## چرا VPS Scope

VPS Scope پس از یک بررسی عملی روی [vernu/vps-audit](https://github.com/vernu/vps-audit) شکل گرفت. آن اسکریپت خودارزیابی VPS را ساده کرد، اما همچنین نشان داد که خواندن مستقیم چند فایل خاص، تعیین آستانهٔ دلخواه بر اساس تعداد پورت یا سرویس و تلقی شکست در جمع‌آوری شواهد به‌عنوان نتیجهٔ امن می‌تواند هشدار اشتباه یا خطر ازدست‌رفته ایجاد کند.

تمرکز پروژه سپس به‌تدریج به سرورهای پراکسی منتقل شد. یک پورت عمومی می‌تواند ورودی عادی Reality یا Hysteria2 باشد، یا پنل، رابط اشتراک و API داخلی‌ای باشد که برای تمام اینترنت باز مانده است. خط مبنای عمومی Linux همچنان ضروری است، اما به‌تنهایی این رابطه‌ها را توضیح نمی‌دهد.

VPS Scope یک fork از vps-audit نیست؛ کد و منطق تشخیص آن به‌طور مستقل پیاده‌سازی شده‌اند.

از OpenAI Codex برای نوشتن بخش عمدهٔ کد Go سپاسگزاریم—تا امروز مقدار کدی که آن نوشته از نگه‌دارندهٔ پروژه بیشتر است و نگه‌دارنده همچنان در حال فهمیدن همهٔ آن است.
