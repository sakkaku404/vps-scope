# VPS Scope

> ابزارهای ممیزی امنیت و سلامت برای پراکسی‌های خودساخته، تونل‌ها و VPS شبکه خصوصی.

VPS Scope یک ابزار حسابرسی VPS است که روی اوبونتو و دبیان اجرا می شود. ابتدا مجموعه کاملی از بررسی‌های میزبان را تکمیل می‌کند: حساب‌های دارای SSH، sudo، فایروال‌ها، جلوگیری از نفوذ، به‌روزرسانی‌های سیستم، بسته‌ها، خدمات systemd، گواهی‌های Docker، TLS، گزارش‌ها، قابلیت اطمینان منابع و تداوم مشکوک. حتی اگر سرور یک سرویس پروکسی را اجرا نمی کند، از این نتایج می توان برای درک وضعیت امنیتی و عملیاتی فعلی آن استفاده کرد.

علاوه بر این مجموعه کلی از ممیزی ها، VPS Scope بیشتر پراکسی های خود ساخته، تونل ها و سرورهای شبکه خصوصی را هدف قرار می دهد. ممیزی های عمومی VPS عمدتاً بر روی افرادی که می توانند وارد سیستم شوند، خدماتی که در حال اجرا هستند، باز بودن پورت ها و وجود خطرات آشکار پیکربندی در سیستم تمرکز می کنند. این چک ها هنوز یک پایه ضروری هستند. اما در سرور پراکسی، شما همچنین باید بدانید که آیا یک پورت شبکه عمومی یک ورودی گره معمولی است یا اینکه نباید در معرض کل پنل مدیریت اینترنت، نقطه پایانی اشتراک یا API داخلی قرار گیرد.

بنابراین VPS Scope وضعیت میزبان لینوکس و بار کاری پروکسی را در یک زنجیره شواهد قرار می‌دهد: پایگاه داده پنل و پیکربندی پروکسی نشان می‌دهند «چه چیزی باید اجرا شود»، systemd، Docker، فرایندها و شنونده‌های واقعی نشان می‌دهند «اکنون چه چیزی اجرا می‌شود»، و فایروال میزبان و پراکسی معکوس نشان می‌دهند «از بیرون چگونه می‌توان به آن دسترسی داشت». گزارش در پایان تلاش می‌کند چند پاسخ مستقیم بدهد:

- آیا خطرات واضحی برای SSH، حساب ها، فایروال ها، به روز رسانی ها و خدمات سیستم وجود دارد یا خیر.
- آیا ورودی های گره مانند Reality، Hysteria2، Shadowsocks واقعاً توسط فایروال نظارت و پردازش می شوند یا خیر.
- آیا پنل های مدیریتی مانند S-UI و 3x-ui به طور تصادفی برای کل شبکه عمومی باز شده اند یا خیر.
- آیا پیکربندی، پایگاه داده پانل، فرآیند در حال اجرا و رابطه نظارت سازگار هستند.
- آیا مشکلاتی وجود دارد که بر ادامه عملکرد سرویس‌های اصلی، گواهی‌های TLS، گزارش‌ها و منابع سیستم تأثیر می‌گذارد.

این نه تنها نام نرم افزار پروکسی را شناسایی می کند و نه به سادگی ممیزی لینوکس عمومی را به اسکن پورت متصل می کند. برای VPS معمولی، گزارش پایه امنیت کامل میزبان را حفظ خواهد کرد. برای پروکسی VPS، به علاوه رابطه هدف بین ورودی گره، سطح مدیریت، اشتراک، کنترل API، Docker و پراکسی معکوس را توضیح خواهد داد.

```bash
curl -fsSL https://sakkaku404.github.io/vps-scope/run.sh | sudo bash
```

در حالت تعاملی می‌توان زبان چینی ساده، انگلیسی، روسی یا فارسی را انتخاب کرد. برای اجرای غیرتعاملی از `--lang zh-CN`، `--lang en`، `--lang ru-RU` یا `--lang fa-IR` استفاده کنید.

به طور پیش فرض، نتیجه گیری در ترمینال نمایش داده می شود و گزارش کامل در VPS ذخیره می شود. VPS Scope هیچ اصلاحی ندارد و SSH، فایروال ها، سرویس ها، حساب ها یا بسته ها را تغییر نمی دهد.

## یک مثال واقعی

موارد زیر مربوط به یک VPS آزمایشی است که S-UI 1.5.3 و sing-box را اجرا می کند و آدرس و اطلاعات نامربوط حذف شده است:

```text
نتیجه ممیزی VPS پروکسی
────────────────────────────────────────────────────────────────────
شناسایی شد: S-UI، sing-box
ورودی‌های پروکسی    PASS
  چهار ورودی تأیید شد؛ پیکربندی، شنونده‌های فعال و فایروال میزبان سازگار هستند.
صفحه مدیریت         RISK/HIGH
  S-UI 56709/tcp · گوش‌دادن عمومی · فایروال مجاز
  TLS فعال · مسیر غیراستاندارد · صفحه مدیریت از کل اینترنت قابل دسترسی است
پیکربندی و اجرا     PASS
  بررسی پیکربندی و وضعیت واقعی پنل ناسازگاری نشان نداد.

ورودی‌های پروکسی:
  443/tcp    sing-box/vless (reality)       عمومی · مجاز · PASS
  443/udp    sing-box/hysteria2             عمومی · مجاز · PASS
  32003/tcp  sing-box/shadowsocks           عمومی · مجاز · PASS
  32003/udp  sing-box/shadowsocks           عمومی · مجاز · PASS
```

همان پنل و فرآیند هسته می تواند چندین پورت شبکه عمومی را باز کند. در معاینه فیزیکی VPS معمولی، به راحتی می توان همه آنها را به عنوان "درگاه های باز" یا "سرویس های پروکسی" در نظر گرفت. VPS Scope پایگاه داده پانل، پیکربندی پروکسی، فرآیند گوش دادن واقعی و فایروال را ترکیب می کند تا تنها صفحه مدیریتی را که واقعاً نباید برای کل شبکه عمومی باز باشد، مشخص می کند.

این تفاوت اصلی با ممیزی عمومی VPS است: حفظ SSH، حساب، به‌روزرسانی و بررسی‌های پایداری لازم و در عین حال درک بیشتر هدف هر ورودی در سرور پروکسی.

## پس از بررسی چه چیزی دریافت خواهید کرد؟

ممیزی تنها یک مجموعه از نتایج را تولید می کند، اما آنها در چهار قالب ذخیره می شوند:

```text
report.fa-IR.html   توصیه می‌شود؛ پس از دانلود با مرورگر باز کنید
report.fa-IR.txt    نسخه متنی برای ترمینال
report.fa-IR.md     گزارش کامل Markdown
report.json         داده کامل ماشین‌خوان برای مقایسه و خط مبنا
manifest.json       فهرست SHA-256 چهار فایل گزارش بالا
```

به عبارت دیگر، ** 4 فرمت مختلف از نتایج آزمون یکسان در فهرست، به اضافه 1 چک لیست **، نه چهار تست وجود دارد.

در پایان اجرا، برنامه مسیرهای کامل پنج فایل را نمایش می دهد و دستور دانلود `scp` را می دهد. فایل HTML در VPS از راه دور ذخیره می شود و نمی تواند مستقیماً مانند یک پیوند وب در ترمینال معمولی SSH باز شود. لطفا آن را در رایانه خود دانلود کنید و برای مشاهده دوبار کلیک کنید:

```bash
scp root@VPS_ADDRESS:'/root/vps-scope-reports/latest/report.fa-IR.html' .
```

اگر VPS Scope نصب شده باشد، می‌توانید در هر زمان آن را پرس و جو کنید:

```bash
sudo vps-scope report show  # نمایش دوباره آخرین نتیجه در ترمینال
sudo vps-scope report path  # نمایش پوشه آخرین گزارش
sudo vps-scope report list  # فهرست گزارش‌های ذخیره‌شده
```

گزارش HTML ابتدا به پنج سوال در مورد "ورودی گره، سطح مدیریت، پیکربندی و عملکرد، در دسترس بودن سرویس و پایگاه امنیتی لینوکس" قبل از نمایش پیشنهادات پردازش و جزئیات فنی پاسخ می دهد. این صفحه از جستجو، فیلتر کردن بر اساس وضعیت، و گسترش همه شواهد بدون بارگیری اسکریپت ها یا فونت های خارجی پشتیبانی می کند.

## VPS Scope چه چیزی را بررسی کنیم؟

### ورودی گره و هواپیمای مدیریتی

- بین پورتال عامل، پنل، نقطه پایانی اشتراک و کنترل API تمایز قائل شوید
- پیکربندی پروتکل مرتبط، گوش دادن به TCP/UDP، مالکیت فرآیند و فایروال IPv4/IPv6
- پورتال‌هایی را پیدا کنید که پیکربندی شده‌اند اما گوش نمی‌دهند، توسط فایروال‌ها مسدود شده‌اند، ناهماهنگی فرآیند دارند یا پس از غیرفعال شدن همچنان در حال گوش دادن هستند.
- تعیین کنید که آیا پنل مستقیماً شبکه عمومی را نظارت می کند، فقط حلقه بک را نظارت می کند یا از طریق Nginx، Caddy، HAProxy در معرض دید قرار می گیرد.
- مسیرهای ریشه/پیش فرض و وضعیت TLS را بررسی کنید، اما مسیرهای تصادفی را به عنوان کنترل دسترسی تلقی نکنید

### پیکربندی و وضعیت در حال اجرا

- تأیید پیکربندی بومی فقط خواندنی sing-box و Xray را انجام دهید
- مقایسه پایگاه داده S-UI، 3x-ui/x-ui، پیکربندی ایجاد شده و نظارت واقعی
- بررسی روابط عملیاتی حیاتی برای Reality، Hysteria2، TUIC، Trojan، Shadowsocks، WireGuard و OpenVPN
- احراز هویت آمار طبقه بندی، دست دادن، DNS، TLS، خطاهای ورود به سیستم مسیریابی و پانل، گزارش های اصلی و داده های کاربر کپی نمی شوند
- دوره اعتبار گواهی، طرح تمدید، نتایج اجرای اخیر و لینک بارگذاری مجدد را بررسی کنید

### Docker و پایه سیستم

- بررسی امتیاز، شبکه میزبان، قابلیت های خطرناک، سوکت Docker و پورت انتشار
- INPUT، FORWARD، DOCKER-USER را با نوردهی واقعی کانتینر مرتبط کنید
- SSH، حساب‌ها، sudo، Fail2ban/CrowdSec، به‌روزرسانی‌ها و خدمات systemd را بررسی کنید
- وجود OOM، core dump، دیسک، inode، ماندگاری گزارش و موارد مشکوک راه اندازی را بررسی کنید
- UID اضافی 0، کلید غیرعادی SSH، برنامه های دایرکتوری موقت و برنامه های حذف شده اما همچنان در حال اجرا را پیدا کنید

## سطح پشتیبانی

"قابل تشخیص" به معنای "پشتیبانی کامل توسط همه نسخه ها و روش های استقرار" نیست. سازگاری فعلی به سه لایه تقسیم می شود:

### کامل ترین تاییدیه

-S-UI
- 3x-ui / x-ui
-sing-box
- هسته Xray

این مؤلفه ها در ترکیب با VPS واقعی، پایگاه داده های پانل، تنظیمات، گوش دادن، فایروال ها و پورتال های پروتکل آزمایش شده اند.

### در حال حاضر انطباق ویژه دارند

مخفی کردن
-مرزبان
-طرح کلی
-WireGuard
-OpenVPN
- Hysteria2، TUIC، تروجان، Shadowsocks

### شناسایی رابطه استقرار

- Docker و Docker نوشتن
-Nginx
-Caddy
-HAProxy

برای نسخه‌های خاص، روش‌های استقرار و معنای تأییدشده، به [سازگاری پروکسی](PROXY-COMPATIBILITY.md) و [ماتریس سازگاری](COMPATIBILITY-MATRIX.md) مراجعه کنید. هنگام مواجهه با ساختارهای ناشناخته پایگاه داده، اهداف پویای پراکسی معکوس یا شواهد ناقص، نتیجه `UNKNOWN` باقی می‌ماند و برنامه وانمود نمی‌کند که امنیت تأیید شده است.

## چگونه نتایج را درک کنیم

این گزارش یک امتیاز ایمنی به ظاهر دقیق اما غیرقابل تفسیر ارائه نمی دهد و تنها از چهار حالت استفاده می کند:

- `PASS`: شواهد از قضاوت فعلی پشتیبانی می کنند، اما به این معنی نیست که سرور همیشه امن خواهد بود.
- `RISK`: مسائلی که نیاز به پردازش یا بررسی دستی دارند پیدا شده است
- `INFO`: حالت، مانیفست یا زمینه، معمولاً نیازی به پردازش جداگانه ندارد
- `UNKNOWN`: شواهد ناکافی یا خواندن ناموفق، نمی تواند به عنوان `PASS` در نظر گرفته شود

هنگام خواندن ابتدا به این موارد توجه کنید:

1. **نتیجه گیری پروکسی VPS**: آیا ورودی گره و صفحه مدیریت نرمال است؟
2. **اکنون اولویت بندی کنید**: مسائلی که بیش از همه شایسته توجه فوری هستند
3. **تاثیر احتمالی بر در دسترس بودن**: مشکلات بازیابی پورتال، فایروال، گواهی یا خدمات
4. **شواهد ناکافی**: بخشی که ابزار نمی تواند به طور قابل اعتماد قضاوت کند

«شاخص نتایج بازرسی» فهرست وضعیت 55 بازرسی است. شواهد کامل در HTML، Markdown و JSON قرار دارد.

## نصب و دستورات رایج

در صورت نیاز به بررسی های منظم، می توانید نصب کنید:

```bash
curl -fsSL https://raw.githubusercontent.com/sakkaku404/vps-scope/main/install.sh | sudo bash
sudo vps-scope
```

بدون پارامتر، بوت چینی/انگلیسی وارد خواهد شد. همچنین می توانید مستقیماً آن را مشخص کنید:

```bash
sudo vps-scope audit --lang fa-IR --profile proxy
sudo vps-scope audit --profile custom --expect-public 22/tcp,443/tcp
sudo vps-scope audit --deep
```

هر دو حالت تعاملی و دستورات اجرای ad-hoc در وب خلاصه ترمینال را نشان می دهند و گزارش کامل را به طور پیش فرض ذخیره می کنند. مکان را به صورت دستی مشخص کنید:

```bash
sudo vps-scope audit --lang fa-IR --profile proxy \
  --format bundle --also-terminal --output ./reports/my-vps
```

اگر از قبل JSON دارید، می توانید گزارش را به صورت آفلاین و بدون اتصال مجدد به سرور بازسازی کنید:

```bash
vps-scope render --lang fa-IR --format html --output report.html report.json
vps-scope verify report.json
vps-scope verify ./reports/my-vps
```

مقایسه دو نتیجه از یک سرور:

```bash
vps-scope diff old.json new.json
vps-scope baseline create report.json baseline.json
vps-scope baseline check baseline.json report-new.json
```

### سیاست صریح و مشاهده از میزبان دوم

شناسایی خودکار پنل‌ها و ورودی‌های رایج پروکسی را می‌شناسد، اما از محدودیت منبع، الزامات TLS و مسیر پنل یا مسیر خروجی IPv4/IPv6 مورد نظر شما خبر ندارد. فایل سیاست این انتظارها را بدون ذخیره اعتبارنامه گره و بدون تغییر سرور ثبت می‌کند:

```bash
vps-scope policy init policy.json
# نقش‌ها، سطح دسترسی و انتظارهای خروجی را ویرایش کنید
vps-scope policy validate policy.json
sudo vps-scope audit --profile proxy --policy policy.json
```

برای بررسی دسترسی واقعی از شبکه‌ای دیگر، روی VPS ممیزی‌شده یک طرح بدون اطلاعات محرمانه بسازید، آن را روی VPS کنترل‌شده دیگری اجرا و نتیجه را وارد کنید:

```bash
vps-scope probe plan --target 203.0.113.10 --output plan.json report.json
vps-scope probe run --output observation.json plan.json
vps-scope probe import --output report-observed.json report.json observation.json
```

نتیجه TCP با سیاست اعلام‌شده مقایسه می‌شود. UDP عمداً `UNKNOWN` باقی می‌ماند، زیرا یک دیتاگرام دلخواه موفقیت دست‌دهی واقعی را ثابت نمی‌کند. `WORK-017` نیز نسخه‌های 3x-ui، sing-box و Xray را آفلاین با تصویر داخلی هشدارهای رسمی تطبیق می‌دهد. نسخه آسیب‌پذیر `RISK` و نسخه نامشخص یا پایگاه قدیمی `UNKNOWN` است؛ نبود تطبیق به معنی نبود سایر آسیب‌پذیری‌ها نیست.

قبل از عمومی کردن گزارش، یک نسخه حساسیت زدایی ایجاد کنید:

```bash
vps-scope redact --format markdown --output public.md report.json
```

ممکن است گزارش‌ها همچنان حاوی روابط حساس استقرار باشند؛ پیش از اشتراک‌گذاری آن‌ها را بررسی کنید. قوانین کامل در [بیانیه حریم خصوصی](PRIVACY.md) آمده است.

## دامنه و محدودیت‌ها را پشتیبانی کنید

در حال حاضر پشتیبانی می شود:

- اوبونتو، دبیان
- لینوکس `amd64`، `arm64`
- استقرار معمولی بومی یا Docker با استفاده از systemd

VPS Scope می تواند پیکربندی و وضعیت عملکردی که در داخل VPS دیده می شود را بررسی کند، اما نمی تواند:

- ثابت کنید که سرور نباید به خطر افتاده باشد
- گروه امنیتی ابر فروشنده را از داخل VPS بخوانید
- اتصال مشتری واقعی و آزمایش شبکه خارج از سایت را جایگزین کنید
- اطمینان حاصل کنید که طرحواره پانل جدید که هنوز تطبیق داده نشده است به درستی قابل درک است

چک های پیش فرض برای عملیات روزانه مناسب هستند. `--deep` علاوه بر این، SUID/SGID، قابلیت‌های فایل و یکپارچگی بسته سیستم را بررسی می‌کند که زمان بیشتری طول می‌کشد. پروژه های عمقی که اجرا نشده اند به صورت اجرا نشده و `PASS` نمایش داده نمی شود.

## بارگیری و تأیید امنیتی

هم اسکریپت‌های اجرا و نصب موقت GitHub Release را دانلود کرده و SHA-256 را بررسی کنید. اگر سیستم قبلاً `cosign` داشته باشد، امضای بدون کلید برای GitHub Actions نیز تأیید می‌شود.

اگر نمی‌خواهید از `curl | bash` استفاده کنید، فایل‌های باینری و `SHA256SUMS` را از [Releases](https://github.com/sakkaku404/vps-scope/releases) به‌صورت دستی دانلود کنید. توضیحات امضا، منشأ و مجوزهای شخص ثالث در [مستندات زنجیره تأمین](SUPPLY-CHAIN.md) آمده است.

## چرا VPS Scope

VPS Scope با بررسی واقعی من از [vernu/vps-audit] (https://github.com/vernu/vps-audit) شروع شد. آن اسکریپت بازرسی خود VPS را آسان کرد و باعث شد متوجه شوم که خواندن فقط یک فایل پیکربندی خاص، تعیین آستانه بر اساس پورت یا تعداد سرویس‌ها، یا تلقی کردن خرابی‌های پزشکی قانونی به عنوان ایمن می‌تواند منجر به مثبت کاذب و منفی کاذب شود.

بعدها به تدریج تمرکز پروژه به سرورهای پروکسی معطوف شد. یک پورت شبکه عمومی ممکن است یک ورودی معمولی Reality یا Hysteria2 باشد، یا ممکن است یک پنل، رابط اشتراک یا API داخلی باشد که در معرض کل اینترنت است. یک خط پایه مشترک لینوکس هنوز ضروری است، اما برای توضیح این روابط استفاده کافی نیست.

VPS Scope شاخه ای از vps-audit نیست و پیاده سازی کد و تشخیص پیاده سازی مستقل هستند.

با تشکر از OpenAI Codex برای نوشتن اکثریت قریب به اتفاق Go - در حال حاضر بسیار بیشتر از خود نگهبانان Go می نویسد که در حال حاضر برای درک آن تلاش می کنند.

```bash
go build -trimpath -o vps-scope ./cmd/vps-scope

```

نمونه‌های قابل تکرار Ubuntu، Debian و استقرار پروکسی پذیرفته می‌شوند. گزارش‌های کامل و ناشناس‌نشده سرور را به issue عمومی پیوست نکنید؛ برای مشکلات امنیتی از گزارش خصوصی آسیب‌پذیری GitHub استفاده کنید. جزئیات در [SECURITY.md](../SECURITY.md) آمده است.
