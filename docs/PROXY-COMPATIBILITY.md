# Proxy compatibility

## 中文

VPS Scope 会把“识别到某个产品”和“能够可靠判断风险”分开。表格里的“已识别”不代表已经理解该产品的所有部署方式或数据库版本。

| 工作负载 | 当前覆盖 | 验证方式 |
|---|---|---|
| S-UI | 原生安装、面板端口、监听与 UFW 暴露、数据库权限、内嵌 TLS 可见性、systemd 上下文 | Debian 13 真实 VPS |
| 3x-ui / x-ui | 原生安装、面板端口、监听与 UFW 暴露、生成的 Xray 配置、数据库权限、systemd 上下文 | Ubuntu 22.04 上的 3x-ui v3.4.2；x-ui 变体使用解析夹具 |
| sing-box | JSON 入口、Clash/V2Ray API、原生 `sing-box check`、敏感文件权限、systemd 上下文 | Debian 12 上的 sing-box 1.13.14 |
| Xray | JSON 入口、API inbound、原生 `xray run -test`、敏感文件权限 | 3x-ui v3.4.2 实际生成的 Xray 配置 |
| Hysteria2 | 原生 YAML 发现、sing-box Hysteria2 入口、UDP 运行上下文 | sing-box 1.13.14 真实入站与解析夹具 |
| TUIC | JSON 入口与 UDP 上下文 | 已有解析夹具，仍需真实主机验证 |
| Trojan / Shadowsocks | 进程和常见配置发现 | 目前仅识别，仍需协议专项实测 |
| Hiddify / Marzban / Outline | 进程、容器和发布端口证据 | 无法区分管理端点时保持 `UNKNOWN`，仍需更多真实面板布局 |
| WireGuard | 进程、服务和敏感文件线索 | 部分识别，尚未实现接口与 peer 策略检查 |
| Docker | 发布地址分类、privileged、host namespace、Docker socket 和宽泛挂载 | Ubuntu 26.04 真实 VPS 上的正常与故意风险容器 |

测试场景包括：被 UFW 阻断的公网通配监听、Docker 回环发布、旧进程仍运行但配置已经损坏、短期 TLS 证书，以及必须确保不会进入报告的假密码和 Token。

提交兼容性问题时，请提供产品版本、安装方式、系统版本、相关服务或容器名称和脱敏报告。不要公开面板数据库或未经脱敏的配置。

## English

VPS Scope separates product detection from security conclusions. A row marked "detected" does not imply that every deployment layout or database version is understood.

| Workload | Current coverage | Validation |
|---|---|---|
| S-UI | Native installation, panel port, listener and UFW exposure, database mode, embedded TLS visibility, systemd context | Real Debian 13 VPS |
| 3x-ui / x-ui | Native installation, panel port, listener and UFW exposure, generated Xray config, database mode, systemd context | Real 3x-ui v3.4.2 on Ubuntu 22.04; parser fixtures for x-ui variants |
| sing-box | JSON ingress inventory, Clash/V2Ray API endpoints, native `sing-box check`, sensitive-file mode, systemd context | Real sing-box 1.13.14 on Debian 12 |
| Xray | JSON ingress and API-inbound inventory, native `xray run -test`, sensitive-file mode | Real Xray generated by 3x-ui v3.4.2 |
| Hysteria2 | Native YAML discovery and sing-box Hysteria2 ingress; UDP runtime context | Real Hysteria2 inbound on sing-box 1.13.14 plus parser fixtures |
| TUIC | JSON ingress and UDP context | Parser fixtures; real-host validation still needed |
| Trojan / Shadowsocks | Process and common configuration discovery | Detection only; protocol-specific real-host validation still needed |
| Hiddify / Marzban / Outline | Process/container discovery and published-port evidence | Safe `UNKNOWN` when the management endpoint cannot be distinguished; real panel layouts still needed |
| WireGuard | Process/service and secret-file signals | Partial detection; interface and peer-policy checks are not implemented yet |
| Docker | Published-address classification, privileged mode, host namespaces, Docker socket and broad binds | Real Ubuntu 26.04 VPS with safe and deliberately risky containers |

The test matrix deliberately includes public wildcard listeners blocked by UFW, loopback Docker publication, broken configuration beside a still-running process, short-lived TLS certificates, and secret-bearing fixture values that must never appear in reports.

When reporting an unsupported layout, include the product version, installation method, OS version, relevant service/container names, and a redacted report. Never publish a panel database or unredacted configuration.
