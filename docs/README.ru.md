# VPS Scope

> Инструменты аудита безопасности и работоспособности для самостоятельно созданных прокси, туннелей и VPS частных сетей.

VPS Scope — это инструмент аудита VPS, работающий на Ubuntu и Debian. Сначала он выполняет полный набор проверок хоста: учетные записи с SSH, sudo, брандмауэры, предотвращение вторжений, обновления системы, пакеты, службы systemd, сертификаты Docker, TLS, журналы, надежность ресурсов и подозрительную устойчивость. Даже если на сервере не работает прокси-служба, эти результаты можно использовать для понимания его текущего состояния безопасности и рабочего состояния.

Помимо этого общего набора проверок, VPS Scope также нацелен на самодельные прокси, туннели и серверы частных сетей. Общие проверки VPS в основном сосредоточены на том, кто может войти в систему, какие службы работают, открыты ли порты и есть ли в системе очевидные риски конфигурации; эти проверки по-прежнему являются необходимой основой. Но на прокси-сервере вам также необходимо знать, является ли порт общедоступной сети обычным входом узла или он не должен быть доступен всей панели управления Интернетом, конечной точке подписки или внутреннему API.

Таким образом, VPS Scope объединяет состояние хоста Linux и прокси-нагрузку в одну цепочку доказательств: база данных панели и конфигурация прокси показывают, «как должно быть», systemd, Docker, процессы и фактические слушатели — «как всё работает сейчас», а брандмауэр хоста и обратный прокси — «как к сервису можно обратиться извне». В конце отчёт старается дать несколько прямых ответов:

- Существуют ли явные риски для SSH, учетных записей, межсетевых экранов, обновлений и системных служб;
- Действительно ли межсетевой экран контролирует и правильно обрабатывает входы узлов, такие как Reality, Hysteria2, Shadowsocks;
- Были ли случайно открыты панели управления, такие как S-UI и 3x-ui, для всей публичной сети;
- Согласованы ли конфигурация, база данных панели, запущенный процесс и взаимосвязь мониторинга;
- Существуют ли какие-либо проблемы, влияющие на непрерывную работу основных служб, сертификатов TLS, журналов и системных ресурсов.

Он не просто определяет имя прокси-программы и не просто привязывает общий аудит Linux к сканированию портов. Для обычного VPS отчет будет содержать полную базовую информацию о безопасности хоста; для прокси-VPS дополнительно объясняется целевая связь между входом в узел, плоскостью управления, подпиской, контролем API, Docker и обратным прокси-сервером.

```bash
curl -fsSL https://sakkaku404.github.io/vps-scope/run.sh | sudo bash
```

В интерактивном режиме доступны упрощённый китайский, английский, русский и персидский языки. Для запуска без диалога используйте `--lang zh-CN`, `--lang en`, `--lang ru-RU` или `--lang fa-IR`.

По умолчанию выводы отображаются в терминале, а полный отчет сохраняется на VPS. VPS Scope не содержит исправлений и не изменяет SSH, брандмауэры, службы, учетные записи или пакеты.

## Реальный пример

Следующее взято из тестового VPS под управлением S-UI 1.5.3 и sing-box, без адреса и ненужной информации:

```text
Заключение по прокси-VPS
────────────────────────────────────────────────────────────────────
Обнаружено: S-UI, sing-box
Входы прокси       PASS
  Подтверждены 4 входа; конфигурация, активные слушатели и брандмауэр согласованы.
Панель управления  RISK/HIGH
  S-UI 56709/tcp · публичный wildcard · разрешено брандмауэром
  TLS включён · путь нестандартный · панель доступна из всего Интернета
Конфигурация       PASS
  Самопроверка конфигурации и фактическое состояние панели согласованы.

Входы прокси:
  443/tcp    sing-box/vless (reality)       публичный · разрешено · PASS
  443/udp    sing-box/hysteria2             публичный · разрешено · PASS
  32003/tcp  sing-box/shadowsocks           публичный · разрешено · PASS
  32003/udp  sing-box/shadowsocks           публичный · разрешено · PASS
```

Одна и та же панель и основной процесс могут открывать несколько портов общедоступной сети. При обычном физическом осмотре VPS их все легко рассматривать как «открытые порты» или все как «прокси-сервисы». VPS Scope объединит базу данных панели, конфигурацию прокси, фактический процесс прослушивания и брандмауэр, чтобы выделить только плоскость управления, которая на самом деле не должна быть открыта для всей общедоступной сети.

В этом главное отличие от общего аудита VPS: сохранение необходимых проверок SSH, учетной записи, обновлений и постоянства при дальнейшем понимании цели каждой записи на прокси-сервере.

## Что вы получите после проверки?

Аудит дает только один набор результатов, но они сохраняются в четырех форматах:

```text
report.ru-RU.html   Рекомендуется: скачайте и откройте в браузере
report.ru-RU.txt    Текстовая версия для терминала
report.ru-RU.md     Полный отчёт Markdown
report.json         Полные машиночитаемые данные для сравнения и базовых снимков
manifest.json       SHA-256-манифест четырёх файлов отчёта
```

Другими словами, в каталоге **4 разных формата одних и тех же результатов тестов плюс 1 контрольный список**, а не четыре теста.

В конце запуска программа отобразит полные пути к пяти файлам и выдаст команду загрузки `scp`. Файл HTML сохраняется на удаленном VPS и не может быть открыт напрямую, как веб-ссылка, в обычном терминале SSH; загрузите его на свой компьютер и дважды щелкните, чтобы просмотреть:

```bash
scp root@VPS_ADDRESS:'/root/vps-scope-reports/latest/report.ru-RU.html' .
```

Если VPS Scope установлен, вы также можете запросить его в любое время:

```bash
sudo vps-scope report show  # снова показать последний результат в терминале
sudo vps-scope report path  # показать каталог последнего отчёта
sudo vps-scope report list  # перечислить сохранённые отчёты
```

Отчет HTML сначала ответит на пять вопросов о «входе к узлу, плоскости управления, конфигурации и эксплуатации, доступности сервисов и базе безопасности Linux», а затем покажет предложения по обработке и технические подробности. Страница поддерживает поиск, фильтрацию по статусу и раскрытие всех доказательств без загрузки внешних скриптов или шрифтов.

## VPS Scope Что проверить?

### Вход в узел и плоскость управления

- Различайте портал агента, панель, конечную точку подписки и элемент управления API.
- Конфигурация ассоциированного протокола, прослушивание TCP/UDP, владение процессом и межсетевой экран IPv4/IPv6.
- Найдите порталы, которые настроены, но не прослушивают, заблокированы брандмауэрами, имеют несоответствие процессов или все еще прослушивают после отключения.
- Определите, контролирует ли панель напрямую общедоступную сеть, контролирует только шлейф или доступна через Nginx, Caddy, HAProxy.
- Проверьте корневые пути/пути по умолчанию и статус TLS, но не рассматривайте случайные пути как контроль доступа.

### Конфигурация и статус работы

- Выполните встроенную проверку конфигурации sing-box и Xray только для чтения.
- Сравнение базы данных S-UI, 3x-ui/x-ui, созданной конфигурации и фактического мониторинга.
- Проверьте критические рабочие отношения для Reality, Hysteria2, TUIC, Trojan, Shadowsocks, WireGuard и OpenVPN.
- Статистика классификации, аутентификация, рукопожатие, DNS, TLS, ошибки маршрутизации и входа в панель, исходные журналы и пользовательские данные не копируются.
- Проверьте срок действия сертификата, план продления, последние результаты выполнения и ссылку перезагрузки.

###Docker и системная база

- Проверьте привилегии, хост-сеть, опасные возможности, сокет Docker и порт публикации.
- Свяжите INPUT, FORWARD, DOCKER-USER с фактическим раскрытием контейнера.
- Проверьте наличие SSH, учетных записей, sudo, Fail2ban/CrowdSec, обновлений и сервисов systemd.
- Проверьте OOM, дамп ядра, диск, индексный дескриптор, сохранение журнала и подозрительные элементы запуска.
- Найдите дополнительный UID 0, ненормальный ключ SSH, программы временного каталога и удаленные, но все еще работающие программы.

## Уровень поддержки

«Узнаваемый» не означает «полностью поддерживаемый всеми версиями и методами развертывания». Текущая адаптация разделена на три уровня:

### Самая полная проверка

-S-UI
- 3x-ui / x-ui
-sing-box
-Xray-ядро

Эти компоненты были протестированы в сочетании с реальными VPS, панелями баз данных, конфигурациями, прослушиванием, межсетевыми экранами и порталами протоколов.

### Уже есть специальная адаптация

-Скрыть
-Марзбан
-Контур
-WireGuard
-OpenVPN
- Hysteria2, TUIC, троян, Shadowsocks

### Идентификация отношений развертывания

- Docker и Docker Составление
-Nginx
-Caddy
-HAProxy

Конкретные версии, методы развертывания и проверенную семантику см. в разделах [Совместимость прокси](PROXY-COMPATIBILITY.md) и [Матрица совместимости](COMPATIBILITY-MATRIX.md). При обнаружении неизвестных структур базы данных, динамических целей обратной генерации или доказательств, которые невозможно прочитать полностью, результатом будет `UNKNOWN` без притворства, что безопасность подтверждена.

## Как понять результаты

В отчете не приводится, казалось бы, точная, но не поддающаяся интерпретации оценка безопасности, в которой используются только четыре состояния:

- `PASS`: Доказательства подтверждают текущее решение, но это не означает, что сервер всегда будет в безопасности.
- `RISK`: обнаружены проблемы, требующие обработки или проверки вручную.
- `INFO`: состояние, манифест или контекст, обычно не требует отдельной обработки.
- `UNKNOWN`: недостаточно доказательств или не удалось прочитать, не может рассматриваться как `PASS`.

При чтении в первую очередь обратите внимание на:

1. **Заключение прокси-VPS**: вход узла и плоскость управления в порядке?
2. **Расставьте приоритеты сейчас**: проблемы, которые больше всего заслуживают немедленного внимания.
3. **Возможное влияние на доступность**: проблемы с восстановлением портала, брандмауэра, сертификата или службы.
4. **Недостаточно доказательств**: часть, по которой инструмент не может достоверно судить.

Окончательный «Индекс результатов проверок» представляет собой справочник состояния 55 проверок. Полные доказательства находятся в HTML, Markdown и JSON.

## Установка и общие команды

Если требуются регулярные проверки, можно установить:

```bash
curl -fsSL https://raw.githubusercontent.com/sakkaku404/vps-scope/main/install.sh | sudo bash
sudo vps-scope
```

Без параметров будет введена китайская/английская загрузка. Вы также можете указать это напрямую:

```bash
sudo vps-scope audit --lang ru-RU --profile proxy
sudo vps-scope audit --profile custom --expect-public 22/tcp,443/tcp
sudo vps-scope audit --deep
```

Как интерактивный режим, так и специальные команды запуска в Интернете отображают сводную информацию о терминале и по умолчанию сохраняют полный отчет. Вручную укажите местоположение:

```bash
sudo vps-scope audit --lang ru-RU --profile proxy \
  --format bundle --also-terminal --output ./reports/my-vps
```

Если у вас уже есть JSON, вы можете восстановить отчет в автономном режиме без повторного подключения к серверу:

```bash
vps-scope render --lang ru-RU --format html --output report.html report.json
vps-scope verify report.json
vps-scope verify ./reports/my-vps
```

Сравните два результата с одного сервера:

```bash
vps-scope diff old.json new.json
vps-scope baseline create report.json baseline.json
vps-scope baseline check baseline.json report-new.json
```

### Явная политика и проверка с другого узла

Автоматическое обнаружение понимает распространённые панели и прокси-входы, но не знает ваших требований к источникам, TLS, пути панели и маршрутам IPv4/IPv6. Файл политики фиксирует эти ожидания, не содержит учётных данных узлов и ничего не меняет на сервере:

```bash
vps-scope policy init policy.json
# отредактируйте роли, доступность и ожидаемые исходящие маршруты
vps-scope policy validate policy.json
sudo vps-scope audit --profile proxy --policy policy.json
```

Для проверки доступности из другой сети создайте план без секретов на проверяемом VPS, выполните его на другом контролируемом VPS и импортируйте наблюдение:

```bash
vps-scope probe plan --target 203.0.113.10 --output plan.json report.json
vps-scope probe run --output observation.json plan.json
vps-scope probe import --output report-observed.json report.json observation.json
```

TCP сравнивается с заявленной политикой. UDP остаётся `UNKNOWN`: произвольная датаграмма не доказывает успешное рукопожатие Hysteria2, TUIC, WireGuard или другого протокола. `WORK-017` также офлайн сопоставляет версии 3x-ui, sing-box и Xray со встроенным снимком официальных бюллетеней. Совпадение уязвимого диапазона даёт `RISK`, неизвестная версия или устаревшая база — `UNKNOWN`; отсутствие совпадения не означает отсутствие других уязвимостей.

Прежде чем опубликовать отчет, создайте десенсибилизированную версию:

```bash
vps-scope redact --format markdown --output public.md report.json
```

Отчеты по-прежнему могут содержать конфиденциальные сведения об отношениях развертывания. Прежде чем делиться ими, просмотрите их самостоятельно. Полные правила см. в [Заявлении о конфиденциальности](PRIVACY.md).

## Объем и ограничения поддержки

В настоящее время поддерживается:

- Убунту, Дебиан
- Linux `amd64`, `arm64`
- Обычное развертывание или развертывание Docker с использованием systemd.

VPS Scope может проверять конфигурацию и рабочий статус, видимые внутри VPS, но не может:

- Докажите, что сервер не должен быть скомпрометирован
- Чтение группы безопасности поставщика облачных услуг из VPS.
- Замените реальное подключение клиента и тестирование сети за пределами объекта.
- Убедитесь, что новая схема панели, которая еще не была адаптирована, может быть правильно понята.

Проверки по умолчанию подходят для ежедневной работы. `--deep` дополнительно проверит SUID/SGID, возможности файлов и целостность системного пакета, что занимает больше времени. Незапущенные проекты глубины будут отображаться как невыполненные, а `PASS` не будет отображаться.

## Загрузка и проверка безопасности

Оба сценария запуска и установки ad hoc загружают выпуск GitHub и проверяют SHA-256. Если в системе уже есть `cosign`, также проверяется подпись без ключа для действий GitHub.

Если вы не хотите использовать `curl | bash`, вы можете вручную загрузить двоичные файлы и `SHA256SUMS` из [Релизы](https://github.com/sakkaku404/vps-scope/releases). Инструкции по использованию подписей, происхождению и лицензиям третьих лиц приведены в [Документации по цепочке поставок](SUPPLY-CHAIN.md).

## Почему VPS Scope

VPS Scope начался с настоящего обзора, который я сделал для [vernu/vps-audit](https://github.com/vernu/vps-audit). Этот скрипт упростил самопроверку VPS и заставил меня понять, что чтение только определенного файла конфигурации, установка пороговых значений по порту или количеству служб или обработка сбоев криминалистической экспертизы как безопасных может привести к ложноположительным и ложноотрицательным результатам.

Позже фокус проекта постепенно переключился на прокси-серверы. Порт общедоступной сети может представлять собой обычный вход Reality или Hysteria2, либо это может быть панель, интерфейс подписки или внутренний API, доступный всему Интернету. Общая базовая версия Linux по-прежнему необходима, но ее недостаточно для объяснения этих взаимосвязей использования.

VPS Scope не является ветвью vps-аудита, а реализация кода и обнаружения являются независимыми реализациями.

Спасибо OpenAI Codex за написание подавляющего большинства Go — в настоящее время он пишет гораздо больше Go, чем сами сопровождающие, которые сейчас изо всех сил пытаются его понять.
